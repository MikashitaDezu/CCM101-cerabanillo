\# Checkpoint 8 - Mission Reflection



Exploring Amazon Web Services, Microsoft Azure, and Google Cloud Platform through this multi-cloud evaluation exercise has provided deep insight into how architectural decisions are driven by unique business requirements. Among the three major providers, Google Cloud Platform impressed me the most with its streamlined container management and advanced data analytics capabilities, particularly through its pioneer work with Kubernetes and high-performance global network routing. 



Despite their distinct consoles and proprietary branding, all three major cloud providers share fundamental similarities in core cloud computing concepts. Each platform relies on foundational virtualization for compute, distributed object buckets for scalable storage, isolated virtual networks for security, and centralized identity and access management models. Understanding these underlying equivalents proves that mastering core cloud principles is far more valuable than memorizing a single vendor's interface.



This activity highlighted that business requirements dictate technology selection. A startup prioritizing low-cost entry and rapid scaling has vastly different infrastructure needs than an enterprise university deeply embedded in a Windows Server ecosystem or a research firm requiring high-performance AI computation. Acting as a Cloud Solutions Consultant demonstrated that technical choices must align with organizational budgets, existing technical stacks, and long-term operational goals rather than mere platform popularity.



Completing this assignment has significantly improved my GitHub Cloud Computing Portfolio by adding structured markdown documentation, comparative matrices, and practical solution frameworks. Organizing these technical reports into a clean repository structure reinforces professional documentation standards and establishes a solid foundation for future cloud engineering projects.
